# Source Verification and Data Feasibility

## Source hierarchy

Use the strongest available source for each claim:

1. official institutional advisor profile;
2. publisher page or DOI record;
3. institutional repository or author manuscript;
4. recognized scholarly index;
5. secondary summaries only for discovery, not as the sole evidence.

For datasets:

1. official API or download page;
2. official data dictionary and terms of use;
3. public archive maintained by the organization;
4. established research dataset with documentation;
5. third-party mirror only when the original is unavailable, and label it.

## Verification record

Keep a compact record for every load-bearing source:

| Field | Required content |
|---|---|
| Source ID | R1, D1, P1, etc. |
| Full title | Exact title as verified |
| Authors/owner | Exact author or organization |
| Type/status | Journal article, proceedings, preprint, official API, etc. |
| Stable link | DOI, publisher, institutional, or official URL |
| Verified claim | What the source actually supports |
| Access date | Date checked |
| Limitation | Paywall, abstract only, incomplete archive, rate limit, etc. |

## Status labels

- **Verified full text**: the full text was opened or downloaded from a reliable source.
- **Verified record**: title, authors, venue, and abstract or metadata were verified, but full text was not accessible.
- **Author or institutional copy**: a manuscript or repository copy was found; label its version.
- **Unverified**: the claim or bibliographic record could not be confirmed. Do not use it as a load-bearing citation.

## Data feasibility checklist

For each dataset, verify on a small sample:

1. the source opens without special institutional access;
2. the required fields are present;
3. the intended time period exists;
4. the unit of analysis is clear;
5. identifiers can be joined across sources;
6. the volume is manageable with the user's tools;
7. terms, privacy, and rate limits permit the proposed use.

Do not promise a full study until this smoke test succeeds. A proposal may state that a source is "to be tested" when only the portal, not the required fields, has been verified.

## Citation discipline

Add an inline citation whenever a sentence:

- summarizes a prior paper's theory, method, or finding;
- states the advisor's research area;
- claims a dataset or API provides a field;
- relies on an official rule, definition, or data limitation.

Do not attach a citation to a sentence that is only the user's proposed design. If a sentence combines prior evidence and a proposed inference, separate the two.

## Common corrections

- Use "declared standard-essential patents" for self-declared patent records.
- Use "conference proceeding" for Academy of Management Proceedings unless a journal version is verified.
- Use "associated with" for observational relationships.
- Say "I did not locate a study in the searched sources" rather than "no one has studied this."
- If a DOI resolves but only an abstract is accessible, say so.
